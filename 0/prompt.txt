Non-blocking notes, most important first:
1. **Silent no-op when the CLI is run through a symlinked path** (`cli.ts`, the `resolve(process.argv[1]) === fileURLToPath(import.meta.url)` guard). I confirmed it: `tsx /tmp/…/cli.ts` exits 0 with no output (macOS `/tmp` is a symlink), while the real path prints the usage line. The installed hook uses a relative path, so it isn't affected, but any absolute symlinked invocation quietly disables the gate. Fix: compare `realpathSync` of both sides, and add a test.
2. **The daemon client's 15s timeout** (`client.ts:15`). If a live-Gemini review or grading call takes longer, it hits the "daemon unavailable" catch in `gate()` and the push goes through, even after the developer typed answers. That's within the fail-open policy, but a slow grader becomes a bypass. Consider a longer timeout for `/answers`.
3. **The terminal exam has no timeout.** An agent that has a terminal but isn't in `AGENT_ENV` (for example the Gemini CLI or Copilot) would hang the push indefinitely.
4. **Model text is printed to the terminal unescaped.** Question text and missed concepts go straight to Ink and to `viva feedback`, so terminal escape codes in model output would be interpreted. Low risk; strip control characters.
5. **Double attestations if saving the decision fails.** In `/answers`, if `writeDecision` throws after attestations were appended, the review stays `awaiting-exam`, so a retry can append them again. Also, `/skip` doesn't check the stage (it can overwrite an `exam-passed`), and it returns a misleading "cannot be skipped" message when a submission is in progress.
6. The `/feedback` route has no loopback-host check, unlike `/code`. The data is low-sensitivity and review IDs are UUIDs, but it's worth adding for consistency.
7. Windows console input (`CONIN$`) is still untested on a real Windows machine, as the PR body says. CI only proves the fallback path.
